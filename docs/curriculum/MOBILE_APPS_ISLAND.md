# 行動應用島（Mobile Apps Island）

> 2026-11-23 開始分批撰寫（自主課程生產，見 [AUTONOMOUS_CURRICULUM_PROGRESS](../planning/AUTONOMOUS_CURRICULUM_PROGRESS.md)）。大綱（標題、目標、概念、先修）取自藍圖，由 `lessons.ts` 的 `mobileFromBlueprint` 讀入。

教學方式是 `web-code` 能力（[WEB0_WEB_CODE_CAPABILITY](WEB0_WEB_CODE_CAPABILITY.md)），和網頁基礎島、響應式設計島相同：範例是可以修改再執行的小頁面，練習以瀏覽器建立的結果檢查。這座島的頁面以手機為準（檢查視窗 360 × 640，預覽可切換寬度），並多用引擎階段 W9（MOB09 與 MOB13 另外用到 W10：模擬的 Service Worker 與快取）：

- **指標步驟**：檢查可以「用手指（或滑鼠）在某個元素按下、移動、放開，或被系統取消」，送出的是真正的 `PointerEvent`；指標捕捉依規格的規則模擬。
- **觸控目標**：`box` 檢查可以寫「至少」與「至多」（例如寬與高都至少 44px）。
- **對話框**：有 `<dialog>` 的頁面，每個操作之後等一個畫格，`close` 事件的結果下一項檢查就看得到；`method="dialog"` 的表單照瀏覽器的行為關閉對話框。

藍圖裡的 `case-study-board`、`decision-simulation` 等尚未建立的互動，在這座島一律以頁面教（`dom-explorer`）：分析型的課給學習者一個有問題的頁面去修，而不是只讀案例。`mobile-nav-sim`、`responsive-sim` 是互動實驗島上既有的獨立實驗，課文以「互動實驗島」提到它們。

## 預覽、檢查與真實手機的差異（課文已說明或避開）

- 檢查在學習者自己的瀏覽器執行，可能是桌機也可能是手機：沒有任何檢查依賴真的觸控、`(hover: …)`、`(pointer: …)` 或 `navigator.maxTouchPoints`。「不靠滑過也看得到」以盒子與 `hit` 判定；預覽裡的 `:hover` 與媒體特徵跟著學習者自己的裝置。
- 檢查裡的指標事件由檢查程式送出，預覽裡的來自學習者自己的滑鼠或手指（MOB04 開頭就說明）。檢查不會有瀏覽器自己接著做的事：`pointerup` 之後沒有 `click`、沒有相容用的滑鼠事件、不會捲動，`touch-action` 沒有可觀察的效果，只有一支指標。指標捕捉是依規格模擬的，所以檢查驗證的是學習者的處理函式，不是瀏覽器的捕捉行為。
- Touch Events（`touchstart` 等）不是每個桌機瀏覽器都有：只出現在課文、表格與測驗的程式片段，不在任何會執行的頁面裡。被動監聽器以 `wheel` 事件示範。
- `touch-action`、`overscroll-behavior` 只檢查計算後的值；效果請學習者在手機上試。系統手勢（邊緣返回、下拉重新整理）無法重現，以課文說明。
- 強制回應的 `<dialog>`：瀏覽器自己的 Escape 關閉需要真的按鍵，檢查裡的對話框一律由按鈕關閉；手工做的抽屜有自己的 `keydown` 監聽器，Escape 可以檢查。指令稿產生的點擊仍會到達 `inert` 的內容，「背後不能操作」以 `inert` 屬性、焦點、`:modal` 與 `hit` 判定。
- 連線時好時壞無法在同一次檢查裡重現：MOB01 的重試練習在主要檢查裡一直失敗（檢查第二次請求與狀態），成功的情形由變體檢查。
- MOB05：檢查與桌機的預覽沒有虛擬鍵盤，手機會顯示哪一種鍵盤、自動完成是否出現也觀察不到：檢查讀屬性，鍵盤遮擋以頁面裡的灰色方塊代替（課文明說是替身），欄位捲動以取得焦點之後欄位相對於視窗的位置判定。平滑捲動在檢查量測時還沒結束，題目請學習者不要用。
- MOB06：`env(safe-area-inset-*)` 在預覽與檢查裡一律是 0，所以頁面把它接到自訂屬性（`--safe-bottom: env(safe-area-inset-bottom, 0px)`），範例用「模擬」按鈕、練習用隱藏的變體把自訂屬性設成例子裡的數值（34px、44px 只是例子）；直接寫 `env()` 的答案在真機上等價，但變體看不出來，題目因此要求用 `var(--safe-*)`。`dvh`、`svh`、`lvh` 在預覽裡都等於框架的高度，工具列出現以 `resize` 到較矮的高度代替。
- MOB07：比較表的每一格都是定性的敘述，不含版本、日期、價格與市占；`chooseRoute` 的規則表是這門課的教學模型（課文明說不是業界標準）。分享按鈕以固定指令稿定義的 `device` 物件檢查，不讀學習者瀏覽器的 `navigator`。
- MOB08：預覽不能安裝任何東西，Manifest 寫成 script.js 裡的 JSON 文字，由頁面裡固定的「檢查器」解析並畫出安裝預覽；檢查器的六條規則就是課文教的規則，課文明說它代替的是瀏覽器自己的檢查（真實網站請看開發者工具的 Application 面板）。`short_name` 最多 12 個字是這門課檢查器的規則，不是規格的規定；顯示模式無法切換，`display-mode` 媒體查詢只在範例裡陳述一般分頁下的事實。
- MOB09、MOB13：沙盒框架註冊不了真的 Service Worker，也沒有 Cache API，兩者由引擎階段 W10 模擬（[WEB0_WEB_CODE_CAPABILITY](WEB0_WEB_CODE_CAPABILITY.md)）：`sw.js` 是頁面的第四個檔案，生命週期依規格的順序走，瀏覽器會強制的規則同樣強制（本文只能讀一次、快取只收 GET、`respondWith` 的時機、沒有網路時註冊不了新版本、文字相同不算新版本）。替身只攔截頁面的 `fetch()` 呼叫，不攔截頁面本身與圖片、樣式表、指令稿的載入，事件之間不會被停止，沒有推播與背景同步；MOB09 第一節就說明，並指向真實網站的開發者工具。離線頁面因此以資料請求的替代回應示範；`location.reload()` 以頁面上的一行文字代替。預覽「重新執行」等於再造訪一次（帶著上一次的 worker 與快取）。
- MOB10：檢查的時鐘是虛擬的，頁面只呈現順序與次數，不量時間；漸變要花真實的時間，「打開」的狀態寫在另一份固定的 HTML 裡檢查。`document.visibilityState` 不能由檢查改變，頁面用固定的替身 `page`（課文對照真正的 API 名稱）。節流下的量測是課文裡的步驟，無法在頁面裡練習。
- MOB11：檢查聽不到螢幕閱讀器，滑動的順序以 Tab 順序與 `focus` 代替（課文說明兩者的差別），使用者的文字大小設定以寫在 `<html>` 上的根字級代替；viewport 設定在預覽的框架裡沒有效果，禁止縮放只以屬性檢查。課文給學習者一份在自己手機上執行的測試腳本。螢幕閱讀器的行為一律以「通常」陳述，WCAG 的要求以文字敘述，不寫條文編號。
- MOB12：「哪一種問題在哪裡驗證」的規則表與測試矩陣是這門課的教學模型（課文明說），裝置清單、分析數字、機型與版本都是虛構並標明；不寫工具的選單步驟與產品名稱。挑裝置的練習沒有換資料的隱藏檢查（答案就是名單），檢查看的是性質：最多四支、沒有缺口。
- MOB13：五關各對應一個練習，後面的關卡把前面的成果放在固定檔案裡。Manifest 沿用 MOB08 的檢查器；「在真機上驗證並記錄結果」頁面檢查不了，最後一節明說並給驗收紀錄表（安裝、離線、螢幕閱讀器、放大文字、橫放、低階裝置）。
- WCAG 的目標尺寸只引用 2.2 版的兩個數字（AA 最低 24 × 24、AAA 加強 44 × 44），其餘尺寸以「常見的建議」陳述，不掛來源；沒有使用統計或市占數字。
