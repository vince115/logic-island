# P9.1b World／Region 3D 場景一致性修正

> 2026-11-19（Asia/Taipei）。分支 `p9/1b-world-from-regions`，程式 commit `56feb78`，基底 `p9/1-visual-prototype` `06e175f`（PR #18）。
> 狀態：**完成，等你看畫面**。沒有合併、沒有修改 Production、沒有啟用世界旗標，沒有新增或搬移 GLB。
> 所有畫面與量測來自本機隔離建置（headless Chromium，SwiftShader 軟體繪製）。**不是真機，不是 Preview。**
> 這一階段只處理「World 與 Region 是同一份場景」與「四時段光影共用」。World → Region 的連續鏡頭移動是下一階段（P9.1c），這裡沒有做：點選區域仍然是換頁。

## 0. 結論

- 世界總覽不再自己產生地形。每個群島就是該區域的 Region Scene Definition 縮小後的樣子：同一批地塊、同一份地形三角形、同一批道路與橋樑、同一批地標與景觀。
- P9.1 的雜訊地形與每區一個的代表建築已經刪除（`src/lib/p9/world-terrain.ts` 整個檔案移除）。
- 五個區域與中央樞紐用**同一個比例尺**繪製，所以世界總覽是一張地圖：25 格的島在每一區都一樣大。
- 世界總覽使用島嶼場景原本的四時段光影，時段由頁首的時間按鈕決定；World、Region、Island 三層讀的是同一個狀態，換層與重新整理都不會重置。
- 既有頁面與 `main` 逐像素相同（11／11），沒有改動任何共用元件。

## 1. 盤點：改之前的資料來源

| | P9.1 的 World（`p9-world-scene`） | Region／Island（`HexWorldExplorer` → `HexWorldScene`） |
|---|---|---|
| 地形 | 自己的高度場：以各島地塊位置為種子，加上雜訊海岸與山脊產生，與區域的地形無關 | `naturalTerrains(world)`：由地塊的種類與高度產生懸崖、沙灘、坡道 |
| 島的座標 | 讀 P8 的 `REGION_LAYOUTS`（不是原型的 CS 版面） | CS 讀 `P9_CS_REGION` |
| 橋與道路 | 只有世界層的 8 條連結；區域內的橋不畫 | `MergedRoutes(world)` |
| 建築 | 每區一個示意地標，位置與造型都是世界層自己訂的 | GLB（`layout.glb`）、程序化地標（`HexLandmarks`）、景觀（`P9Landscapes`） |
| 樹 | 依高度場與雜訊散佈 | `layout.natural.trees`（v2.1 GLB 的樹） |
| 光影 | 自己的一組燈，固定白天 | `ENVIRONMENTS` 四時段 → `HexEnvironment`，時段來自 `useSiteTime()` |
| 比例 | 每區各自的寬度（手動指定再放大 1.3 倍） | — |

所以 P9.1 的世界層是另一份視覺，而且連 CS 的島形都與 `/p9/cs` 不同。

## 2. Region Scene Definition

`src/lib/p9/region-scene.ts`。每個區域（與樞紐）一份定義，內容就是 Region 頁面原本在用的那份版面（以物件相等保證，不是複製）：

| 欄位 | 內容 |
|---|---|
| `region` | 區域的地圖：地塊與高度、橋、碼頭、GLB 擺放、森林、自然配置。CS 是原型的版面，其餘四區是已核准的版面 |
| `islands` | 每座島的 `islandId`、`regionId`、中心、格數、最高點 |
| `landmarks` | 每個地標站在哪座島的哪一格：GLB 建築取自擺放資料，程序化地標與景觀取自各自的資料 |
| `landscapes` | 規劃中島嶼的景觀 |
| `trees` | 區域擺放的每一棵樹 |

Region 頁面（`P9RegionExplorer`）與世界總覽（`P9WorldScene`）都呼叫同一個 `regionScene(id)`。世界層沒有自己的地形、島嶼座標或建築清單。

## 3. World 怎麼畫（LOD）

`src/components/p9/p9-region-miniature.tsx`：把一份定義放進一個等比例縮放的群組，用區域自己的地圖座標繪製。細節層級只改變「怎麼畫」，不改變「在哪裡、長什麼形狀」：

| 內容 | World | Region |
|---|---|---|
| 陸地 | 區域的同一批地形三角形，整區合併成一個 mesh | 每座島一個 mesh |
| 道路與橋 | 區域的同一個元件（`MergedRoutes`） | 同左 |
| 程序化地標 | 區域的同一個元件（`HexLandmarks`） | 同左 |
| 規劃中島嶼的景觀 | 區域的同一個元件（`P9Landscapes`） | 同左 |
| GLB 建築 | 在每棟建築自己的擺放位置與朝向放一個簡化替身；**不載入 GLB** | 載入 GLB |
| 樹 | 在每棵樹自己的位置放一棵低面數的樹；不載入 GLB | GLB 的樹 |
| 海 | 區域的淺灘漸層（`seaGrid`），沒有浪花 | 完整的海與浪花 |
| 不畫的 | 岩石、廣場的設施、名牌、區域內的互動 | 全部都有 |

世界層自己負責的只有三件事：各區放在哪裡（`WORLD_MAP` 的位置、環序、關聯橋，沒有改）、樞紐橋與關聯橋、外海。

**同一個比例尺。** P8 的總覽替每區手動指定寬度，結果 CS 的比例只有樞紐的一半。現在每個場景都用同一個比例（桌機 0.58、手機 0.35），區域的寬度不再是資料，而是「它自己的地圖有多寬 × 比例」。單元測試確認這樣的寬度在兩種構圖下都不重疊、連結不穿過別的區域。

**其餘四區。** 它們的定義是已核准的版面，所以在世界總覽上就是實際的樣子：19 格的島、橋與道路，沒有樹也沒有建築。P8 蓋在規劃中島嶼上的白霧在世界層不畫。這四區看起來單調是資料的現況，不是世界層另外簡化的結果。

## 4. 四時段光影

盤點到的既有系統（沒有新增第二套）：

| 項目 | 位置 |
|---|---|
| 時段與名稱 | `morning` 清晨、`noon` 中午、`sunset` 黃昏、`dusk` 傍晚（`src/lib/site-time.ts`）。沒有名為「夜晚」的時段，最暗的是傍晚 |
| 狀態 | 全站一個，存在 `localStorage`（`logic-island.time`），以 `useSiteTime()` 讀取 |
| 控制 UI | 頁首的時間按鈕（`theme-toggle.tsx`），桌機與手機都有；傍晚同時切換深色主題 |
| 每個時段的內容 | `src/lib/islands/environments.ts`：背景、環境光、半球光、太陽（顏色、強度、方向）、陰影參數、海面色調、建築發光強度與色調。霧在四個時段都是關閉的 |
| 繪製 | `HexEnvironment`（燈與陰影）、`GlowProvider`／`useGlow`（發光材質） |

世界總覽現在直接使用這些：同一個 `HexEnvironment`、同一份 `ENVIRONMENTS`、同一個 `useSiteTime()`。唯一的差別是陰影範圍：世界比單一區域寬得多，所以陰影盒一律依太陽方向貼合整個世界，陰影貼圖用 2048。顏色、強度、太陽方向、海面色調與發光都沒有另外設定。

因為三層讀的是同一個全站狀態，World → Region → Island 之間換頁、上一頁或重新整理都維持同一個時段，E2E 有檢查。

傍晚時群島的輪廓、道路與橋都看得出來；地標在世界層是實際比例，燈塔的發光只有幾個像素（§7-2）。

- **世界總覽的三角形加倍、draw call 變成五倍。** 這是畫出實際島嶼的代價：29 座島的地形、每一座橋的欄杆與橋板、每個程序化地標的零件。它現在在「區域地圖」的暫定預算之內（150 個／150k），遠超過為「只畫輪廓」訂的世界預算（15 個／20k）。我沒有為了壓數字而簡化島形。

- 腳本量曾經在第一版增加到 1080 KB：共用定義把整份課程登錄資料帶進了前端。修正後定義只含空間資料（`56feb78`）。

## 7. 已知問題

1. **世界層的 draw call 與三角形超過世界層的暫定預算**（§6）。可以再合併的有橋的零件與程序化地標；要不要做、世界層的預算訂多少，建議等真機量測後決定。
2. **地標在世界層是實際比例，很小**（燈塔約 20 px）。位置正確，但從世界總覽不容易認出是什麼。放大地標會偏離「縮小的實際場景」，所以沒有做。
3. **CS 在兩層的朝向不同。** Region 頁面的相機預設把 CS 轉了 295°（為了讓島在畫面上最大），世界總覽用的是預設視角。島的相對位置相同，但畫面上是旋轉過的。這是相機預設，不是地理資料；P9.1c 的連續鏡頭會需要處理它。
4. **其餘四區只有地形與橋**，因為它們的資料就是這樣（§3）。
5. **GLB 建築在世界層是簡化替身**，造型由程式拼成；位置與朝向取自擺放資料。
6. **World → Region 仍然是換頁**，沒有鏡頭過渡。這是 P9.1c 的範圍。
7. 沒有真機、沒有 Preview、沒有記憶體量測。
