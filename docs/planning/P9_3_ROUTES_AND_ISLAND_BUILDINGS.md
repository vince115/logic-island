## 2. 做法（Phase B）

- **建築是資料**：`src/components/p9/landmarks/kit.ts` 是低多邊形零件與組件（hall、tower、mast、panel、plinth、lamp）；每座島是一份零件清單（`cs.ts`、`ai.ts`、`design-web.ts`、`sys.ts`；資料結構島保留在 `structures.ts`），由 `landmarks/index.ts` 依島嶼 ID 登錄。
- **一個渲染器**：`p9-landscapes.tsx` 把一個區域所有島的建築合成一個 mesh，夜間發光的窗戶、螢幕、燈另成一個 mesh，強度跟著時段（`useGlow`，與 GLB 窗戶相同）。World 與 Region 用同一份資料，World 省略細節零件（`fine`）。
- **建築位置**：`src/lib/p9/island-sites.ts` 從實際道路與橋樑線段挑選建地：離所有道路／橋樑中心線 ≥ 0.72、不是廣場、不是橋頭、不是 spur 終點、不是海岸。
- **規劃中島嶼也是完整的島**：`src/lib/p9/built-region.ts` 對 AI／Design／Web／SYS 的每座島移除霧、主建地抬高一階、外圍加樹林；島嶼 ID、中心、輪廓、橋樑、相機不變。「規劃中」仍由世界資料決定：名牌顯示規劃中、沒有課程連結，建築也不可點擊。
- 基礎程式島維持 GLB 與互動；資料結構島維持 P9.2 的建築，只補上夜間燈光。

## 5. 尚未完成與風險

1. **沒有真機數據**：量測是 headless Chromium（Metal），不是 iOS Safari／Android Chrome。
2. **World 三角形增加約 34k**：draw call 沒有增加；若真機吃緊，可以把更多零件標為 `fine`（World 不畫），不需要改島的外形。
3. **SYS、Design 的區域全景**：地圖比例較小，建築在全景裡偏小，近景清楚；之後可考慮依區域調整建築比例。
4. **夜間發光偏含蓄**：窗戶與螢幕共用一個暖色發光，沒有個別顏色。
5. **資料結構島的 Registry 同步、GLB 與互動規格**：依指示列為後續，現有模型未刪除或重做。
6. 新建築都是程序產生的低多邊形零件，不是 GLB；若要換成正式 GLB，需另外的建模授權（S1 §10.2）。
