# 跨島學習路線（Learning Paths）

> Phase F.0 規劃文件（2026-11-02）。路線資料：[`data/learning-paths.json`](data/learning-paths.json)；每堂課：[CURRICULUM_320_BLUEPRINT](CURRICULUM_320_BLUEPRINT.md)；島嶼：[ISLAND_TAXONOMY](ISLAND_TAXONOMY.md)。
> 除了路線 A（全部是已完成的 60 堂），其他路線包含的都是**規劃中**的課程。

## 1. 先修的種類

| 種類 | 資料欄位 | 意義 | 介面（規劃） |
|---|---|---|---|
| **必修先修** | `prerequisites` | 不懂就學不下去；路線一定包含 | 課程頁標「必修」；不鎖課程，只提示 |
| **建議先修** | `recommended` | 有幫助但非必要 | 標「建議」，可略過 |
| **選修** | 路線的 `targets` 以外、同區的島 | 延伸 | 路線頁列「延伸島嶼」 |
| **跨島連結** | 不同島之間的必修或建議 | 例如 AIF05 必修 A16、DB11 必修 D14 | 地圖上以航線表示 |
| **課程缺口** | `gaps` | 需要但本課程沒有教 | 標「需要外部背景」，見 §4 |

學科島**不硬鎖**：任何課程都能直接開啟，先修只是提示（沿用現有 60 堂「先修只是建議」的做法）。

## 2. 路線如何組成（可機器驗證）

每條路線＝**目標課程**（`targets`）＋目標課程的**全部必修先修（遞移閉包）**，依依賴順序排列（`lessons`）。驗證器檢查每堂課的必修先修都在路線內且排在前面，見 [CURRICULUM_320_BLUEPRINT#驗證](CURRICULUM_320_BLUEPRINT.md#驗證)。

| 路線 | 目標 | 課數（含被帶入的先修） | 經過的島 | 含 ML／DL |
|---|---|---:|---|---:|
| A APCS／資訊科學基礎 | F、DS、AL 全部 | 60 | F → DS → AL | 0 |
| B 軟體工程 | PL、DB、SA 全部 | 86 | F → DS → PL → DB → SA | 0 |
| C 網路與系統 | CN 全部＋DB 的整合課（DB01、DB02、DB03、DB05、DB14、DB16、DB17、DB19） | 54 | F → DS → AL → PL → DB → CN | 0 |
| D 企業資訊系統 | DB、SA、MIS 全部 | 84 | F → DS → PL → DB → SA → MIS | 0 |
| E AI 研究 | AIF、ML、DL、GEN 全部＋LLM 模型軌 | 142 | F → DS → AL → CN → AIF → ML → DL → LLM → GEN | 50 |
| F AI 應用工程 | LLM 應用軌、AG 全部、OPS 非 MLOps 課（16 堂）＋CN12、CN14、DB03、DB16 | 89 | F → PL → DB → CN → SA → AIF → LLM → AG → OPS | **0** |

## 3. 各路線

### A — APCS／資訊科學基礎（已完成）

- **必修**：F01–F20 → D01–D20 → A01–A20（現有教材的建議順序）。
- **延伸**：PL（語言原理）、AIF（以 A14–A16 為基礎的 AI 搜尋）。
- **成果**：能用四種語言寫出並分析 APCS 程度的程式與演算法。
- 未來的 APCS Trial 挑戰島（F.6）以此路線為範圍。

### B — 軟體工程

- **核心**：PL → DB → SA；帶入 F 的 17 堂與 DS 的 9 堂（物件導向與樹相關先修）。
- **建議（不在路線內）**：A01、A04、CN01、CN14 等 13 堂。
- **延伸**：CN（API 與部署環境）、MIS（企業情境）、OPS（上線與維運）。
- **成果**：能從需求、建模、資料庫設計到架構與測試，完成一個小型系統的設計文件與原型。
- **缺口**：作業系統（PL13、PL14 的執行緒）、軟體工程實務（版本控制，SA18）。

### C — 網路與系統

- **核心**：CN 全部＋DB 的整合課；帶入 F、DS（佇列、圖）、AL（A14 BFS、A16 最短路徑，用於路由協定）、PL01–PL02、DB07。
- **延伸**：OPS（部署、可觀測性）、SA12（架構風格）。
- **成果**：能追蹤一個 HTTP 請求從 DNS、TCP、TLS 到資料庫的完整路徑，並建立一個有 API 與資料庫的網路服務。
- **缺口**：雲端平台（DB19）。

### D — 企業資訊系統

- **核心**：DB → SA → MIS；帶入 F 的 14 堂、DS 的 8 堂、PL01–PL02。
- **延伸**：CN18（安全）、OPS17（AI 系統法規）、AIF19（負責任 AI）。
- **成果**：能分析企業流程、設計資訊系統並評估 ERP／BI 等方案的商業價值與風險。
- **缺口**：機率（MIS13 決策支援的期望值）、軟體工程實務。

### E — AI 研究

- **核心**：AIF → ML → DL → LLM（模型軌）→ GEN；帶入 F 的 15 堂、DS 的 9 堂、AL 的 8 堂（搜尋、分治、回溯），以及 LLM 應用軌的 4 堂（LLM01、LLM09、LLM10、LLM20，模型軌的評估與對齊課需要）與因 LLM09（API）帶入的 CN 5 堂。
- **數學先修**：**課程中沒有**；路線中有 11 堂標 `linear-algebra`、9 堂 `probability`、8 堂 `calculus`、2 堂 `statistics` 缺口，見 §4。
- **成果**：能從原理推導並以 PyTorch 實作與訓練神經網路，理解 Transformer、LLM 預訓練與對齊、擴散模型。

### F — AI 應用工程

- **核心**：API／資料基礎（CN12、CN14、DB03、DB16）→ LLM 應用軌（API、提示、結構化輸出、RAG、向量檢索、評估）→ AG 全部 → OPS 工程軌。
- **不需要 ML／DL**：驗證器確認這條路線**沒有任何 ML 或 DL 課程**；路線帶入的 LLM02（tokenization）、LLM03（embeddings）屬模型軌，但不需要 ML／DL。DL01、DL18 等只列為「建議」。
- **帶入的其他先修**：F 的 12 堂、PL01–PL02、DB01／DB02／DB07、CN 的 5 堂、SA01／SA04／SA05／SA16（需求與測試）、AIF01／AIF03（代理人概念）。
- **延伸（MLOps）**：OPS05、OPS09、OPS10、OPS12 需要 ML／DL，屬路線 E 與 F 的交會。
- **成果**：能設計、實作、評估並上線一個以 LLM 與工具呼叫為核心的 AI 應用，包含 RAG、Agent、監控與成本控制。

## 4. 課程缺口

這些背景知識**沒有任何島在教**；藍圖以 `gaps` 標記，沒有假裝有對應課程。

| 缺口 | 用到的課（藍圖） | 影響 | 建議處置（需決定） |
|---|---|---|---|
| 線性代數 | 12 堂（ML、DL、LLM、GEN、AIF16） | 路線 E 的核心 | 新增「數學補給站」橋接模組（不計入 320），或明列外部資源 |
| 機率 | 10 堂 | AIF／ML／GEN、MIS13 | 同上；AIF13 只涵蓋 AI 需要的部分 |
| 微積分 | 8 堂（梯度、反向傳播、擴散） | 路線 E | 同上 |
| 統計 | 6 堂（ML 評估、OPS 監控） | 路線 E、F | 同上 |
| 離散數學 | 1 堂（AIF12 一階邏輯） | 小 | 在課內補充 |
| 作業系統 | 4 堂（PL13、PL14 並行、CN、OPS） | 路線 B、C | 未來可評估第 16 座島或併入 PL |
| 雲端平台 | 2 堂（DB19、OPS） | 路線 C、F | 以概念與開源工具教，不綁廠商 |
| 軟體工程實務（版本控制、程式碼審查） | 3 堂（SA18 等） | 路線 B、F | SA18 涵蓋概念；Git 實作可作為實驗島活動 |

| 傳統電腦視覺（OpenCV、AOI） | 舊 AI-05 | 部分在 DL（CNN）與 GEN | 未來評估 |
| AIoT／Edge AI | 舊 AI-06 | 部分在 OPS（部署、量化） | 未來評估 |

## 5. 撰寫時協調的邊界

藍圖由四組撰寫者並行草擬（每組 3 座島），以「錨點課」互相引用；完成後主線補上了非錨點的跨島**建議**連結，並記錄以下邊界決定：

| 主題 | 歸屬 | 另一側 |
|---|---|---|
| 函式呼叫（單次） | LLM13 | 多步工具迴圈 AG03（建議 LLM13） |
| Context 管理 | LLM11（一般）| AG08（Agent 專屬：壓縮工具結果、外部筆記，建議 LLM11） |
| Prompt injection | LLM18（基本）| AG18（間接注入、資料外洩，建議 LLM18） |
| KV cache、推論 | LLM22（原理）| OPS07（GPU 記憶體預算、服務設定，建議 LLM22） |
| 模型匯出 | DL24 | OPS05（打包已匯出的模型，建議 DL24） |
| 實驗追蹤 | DL21 | OPS09（模型註冊，建議 DL21） |
| 應用評估 | LLM24 | OPS15（上線後評估管線，建議 LLM24） |
| 資料倉儲／OLAP | MIS11（商業面，需 DB03） | DB 不另教 |
| 安全與倫理 | CN18（網路）、MIS15（管理）、MIS16（法規）、AIF19（負責任 AI） | LLM／AG／GEN 只教模型專屬的風險並引用 AIF19 |
| 測試 | SA16（軟體測試） | OPS15（AI 上線評估） |
