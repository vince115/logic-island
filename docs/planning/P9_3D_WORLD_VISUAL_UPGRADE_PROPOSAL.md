## 0. 結論

1. **「看起來像六角形節點關係圖」是設計造成的結果，不是 bug。** 世界總覽刻意只畫「每座島的六角地塊縮小後的輪廓＋連線」（15 個 draw call）；區域地圖裡 29 座島有 25 座是「規劃中」，被畫成蓋著白霧的 19 格平板加一支旗子；五個區域之間只有顏色不同。有地形、樹與建築的只有 CS 的 4 座島，而真正用到 GLB 建築的只有 1 座。
2. **三層架構可行，而且骨架已經在**：`/world` → `/world/<region>` → `?island=<id>` 三層的路由、資料、鍵盤與焦點管理都已存在並通過 A1-L。P9 要換的是「每一層畫什麼」，不是導覽。
3. **建議採方案 B（程序化地形＋每區一套建築 Kit）**，先用不需要新模型的方案 A 做第一個 Prototype。不建議一次做 29 座專屬模型（方案 C）。
4. **對 P8 Activation**：Production 旗標本來就是關的，沒有東西要回退。建議 A1-P 只當作「路由／導覽／安全」的基礎驗收；視覺批准點與 A2 真機驗收延到 P9 的畫面上再做。
5. **需要你決定的事**在 §9。其中「建模」與「從 `m3/*` 搬資產」依專案規則需要另外授權，本提案沒有預設已取得。

### 2.1 已經存在、可以直接沿用的機制

- **資料分層**：內容（`src/content/world`：區域、島、狀態、課程數）與空間（`src/lib/islands/regions`：位置、橋、相機、主題）已分開，測試會比對兩邊的 id。P9 只需要擴充空間這一側。
- **美術分級的型別已經定義**：`IslandVisual { state: 'open' | 'planned'; tier: 'glb' | 'landmark' | 'outline' }`（`regions/schema.ts`），P8.1 架構文件稱為 T2／T1／T0。P9 等於是把大多數島從 T0 提升到 T1／T2。
- **自然地形產生器**：`hex-terrain-natural.ts`、`hex-natural-scene.ts` 從地塊資料產生連續地形（懸崖、沙灘、台地）。目前只有 `natural: true` 的版面（CS 開放島）使用；格點地圖沒有接上。
- **植被與岩石**：`HexForest` 以 InstancedMesh 重複使用 v2.1 GLB 裡的 5 棵樹，並有距離 LOD（`tree-lod.ts`）；`HexRocks` 沿海岸放岩石。
- **GLB 零件擺放**：`HexGlbPlacement` 以「節點名稱＋地塊＋朝向」把 GLB 裡的任一子樹放到地圖上，原始檔不動（`hex-buildings.ts`、`glb-parts.ts`）。這就是 Kit 化需要的機制。
- **互動**：GLB 目標的隱形點擊代理（手機至少 1.6 世界單位寬）、聚焦時的地面標記、HTML 對應的 POI 按鈕（`HexPoiPanel`）、hover、資訊泡泡。
- **環境**：四個時段、靜態陰影、自動旋轉、自由相機，都已在 `/islands` 候選頁驗收過。

### 2.2 需要新增或擴充的地方

| 項目 | 現況 | 需要 |

## 4. 視覺方案與成本比較

| | A. 程序化地景 | B. 區域建築 Kit（建議） | C. 每島專屬模型 |

成本欄是相對比較，不是工時估計；目前沒有足以估工時的依據。下載量與 draw call 是由既有量測外推的估計，Prototype 會量出實際數字。

**建議 B，分兩步走**：先做 A 的範圍當 Prototype（§7），確認「地形＋比例＋世界層陸塊」能不能把畫面從圖表變成群島；通過後再為一個區域做第一套 Kit。A 的成果在 B 裡全部保留，沒有重工。

## 5. 各層的設計提案

### 5.1 World：五個大型群島區域

- 每區畫成**一塊有輪廓的陸塊群**：由該區的島嶼位置推導出共用的淺灘與主要陸塊，加上起伏、海岸、區域配色，以及**一個從遠處就認得出來的代表地標**。島與島之間的橋在這一層不畫。
- 29 座島不再逐一出現。每區的名牌保留現有資訊（幾座學科島、幾座已開放）。
- 區域間的連結從直線長方體改為較低調的航線或長堤；環序、3 座關聯橋與樞紐的拓樸資料不變。
- 預算：每區 2 個 mesh（陸塊、地標）＋樞紐 2＋海 1＋連結 1–2，可以守住 ≤ 15 個 draw call、≤ 20k 個三角形。
- AI 的六瓣配置保留：在世界層呈現為一圈環礁圍著潟湖。

### 5.2 Region：4–8 座有地形與建築的主題島

- 每座島有自己的形狀與高度（目標 30–40 格，像現在的基礎程式島，而不是 19 格平板），接上自然地形、該區的植被與岩石。
- 排列改為人工擺放的資料（與 CS 相同的做法），不再是等距格點。已核准的配置原則不變：AI 六瓣、各區的橋與關聯、新課程不自動重排。
- **比例**：島變大之後，整個區域不一定要一次塞進畫面。區域地圖已經支援平移、縮放與鍵盤操作；提案是預設視角仍然看得到整個區域，但建築與地形起伏加大（建築縮放從 0.6 往上調），讓每座島在全景下就有可辨識的輪廓。手機上是否改為「預設看 2–3 座島、其餘用平移」要用 Prototype 比較後決定。
- 已開放與規劃中的差異見 §5.4。

### 5.3 Island：探索建築、互動物件與課程入口

- 網址維持 `?island=<id>`，Escape 仍然是 島 → 區域 → 世界。
- 聚焦時相機更低、更近；建築是可點的目標，對應這座島的科目（現有的 `LearningUnit`），點擊後打開科目面板的對應段落或進入課程。每個 3D 目標都有 HTML 對應按鈕（沿用 `HexPoiPanel` 的做法），鍵盤與觸控都能用。
- 桌機的右側面板與手機的 Bottom Sheet 不變；相機已經會避開面板與 Sheet 的範圍取景，這個機制沿用。
- 是否需要獨立的單島路由（例如 `/world/<region>/<island>`）先不決定；`?island=` 已能滿足，新增路由等有具體需求再提。

### 5.4 已開放與規劃中島嶼

| | 現在 | 提案 |
|---|---|---|
| 地形與景觀 | 白霧蓋住的平板 | 與開放島相同的完整地形、植被 |
| 建築 | 沒有，只有測量旗 | 顯示「尚未啟用」的狀態：地基、鷹架或關著的建築（美術定案時選一種），不發光 |
| 互動 | 點島可聚焦；面板顯示「規劃中」與預計堂數；連結只到區域的課綱大綱 | 相同。**建築不是可點目標，不產生課程入口** |
| 標示 | 名牌與清單的「規劃中」標籤 | 保留 |

防呆以資料與測試保證，不靠畫面：課程入口只由已發布的課程產生；單元測試檢查規劃中島嶼沒有任何 `route` 目標；E2E 沿用現有的「25 座規劃中島沒有課程連結」檢查（V-08）。

### 5.5 桌機與手機

- 沿用既有做法：1240 px 以下名牌改為圖釘、手機 44×44 的觸控範圍、Bottom Sheet 佔地圖 ≤ 60%、單指左右旋轉且不攔截頁面捲動。
- 世界層在手機上無法同時讓五個區域都夠大。提案：手機的世界總覽保留全景作為入口，點選區域後相機先飛到該區並顯示預覽，再進入區域頁。
- 手機效能是最大的未知數：真機 FPS 從未量過。P9 的每個階段都要在 A2 的裝置清單上量測，不以桌機或模擬手機代替。
