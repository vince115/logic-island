位置是 `WORLD_MAP`（[world-map.ts](../../src/lib/islands/regions/world-map.ts)）裡的資料，單位是對齊螢幕的海面座標 `[右, 遠]`，中央樞紐在原點。本階段**沒有移動任何 Region**（與 P8.2 相同），只把手機版 SYS 標籤的偏好邊由上改為下。

| 中央樞紐（互動實驗島） | `[0, 0]`／8 | `[0, 0]`／6 | 中央 |
| CS 程式與資訊群島 | `[-4, 30]`／30 | `[-1, 28]`／19 | 上 |

| WEB 網頁與應用開發群島 | `[-13, -28]`／19 | `[-10, -23]`／13 | 左下 |

環序（順時針）：`ring: ['cs', 'ai', 'design', 'web', 'sys']`。「相鄰」的定義是在這個環上前後相接（最後一個與第一個也相接）。`validateWorldMap` 會檢查環序與兩種構圖在螢幕上的順時針順序一致，所以資料上的相鄰就是畫面上的相鄰。

### 2.2 連接規則與對應的檢查

| 你的規則 | 做法 | 檢查 |
|---|---|---|
| 1. 中央樞紐可連接全部五個 Region | 樞紐橋不逐一列出，由環上的每個 Region 各產生一條（`worldLinks`）；新增 Region 自動得到一條 | 單元測試：樞紐橋 = 環上每個 Region 各一條；環 = registry 的全部 Region |
| 2. 相鄰 Region 之間可以建立關聯橋 | `bridges` 清單，每一筆是一對 Region | `validateWorldMap`：橋的兩端必須是已放置、不同、且在環上相鄰的 Region；同一對不能重複 |
| 3. 不要求每一組有關聯的 Region 都有橋 | 橋是清單，不是由關聯推導 | AI—DESIGN 相鄰而無橋；CS—WEB、CS—DESIGN、AI—SYS、AI—WEB 有課程關聯而無橋（不相鄰） |
| 4. 不相鄰的 Region 透過中央樞紐導航 | 區域地圖的清單只列出有關聯橋的 Region，其餘走「世界總覽」（§3） | E2E：每個區域頁只連到 `bridgedRegions` 的 Region；CS → AI 直達、AI → DESIGN 經世界總覽 |
| 5. 不因先修數量變化而自動重排 | `world-map.ts`、`region-layouts.ts`、`lattice-layout.ts` 不 import 課程、目錄或關聯模組 | 單元測試讀原始檔確認沒有這些 import；`WORLD_MAP` 只有 `hub`／`regions`／`ring`／`bridges` 四個鍵 |
| 6. 橋不遮擋島嶼、地標或互動標籤 | (a) 橋面高度 0.24，低於規劃中的島（0.32）與已開放的島（0.5），不可能畫在島上；(b) 每條橋取兩個輪廓之間最短的跨距；(c) 標籤避開橋（§2.4） | `validateOverviewLinks`：橋不得進入任何它沒有落腳的地塊、橋與橋不得交叉（兩種構圖）；E2E：實際頁面上標籤不壓到橋、不蓋住島（六種尺寸） |

### 2.4 3D 構圖

- **樞紐橋**：淺石色、一整段不中斷的橋面，較寬（桌機 0.55、手機 0.36）。
- **關聯橋**：暖木色、一段一段的木板，較窄（桌機 0.42、手機 0.28）。兩種橋不只靠顏色區分：一種連續、一種分段。
- **落點**：每條橋連接兩個輪廓之間**最近的兩個地塊**。不需要手寫端點，Region 的地圖或位置改了仍然有效，而且最短跨距不會越過它所連接的輪廓的其他地塊。P8.2 的渡輪虛線（由碼頭到樞紐）已由樞紐橋取代。
- **標籤**：每個標籤先掛在 `WORLD_MAP` 指定的那一邊；會壓到橋、蓋住島或碰到別的標籤時，沿著那一邊滑開，滑不開才換到輪廓的另一邊（[overview-labels.ts](../../src/lib/islands/regions/overview-labels.ts)，純函式）。
- **短標籤**：舞台的可用寬度小於 720 px 時（手機，以及導覽在旁的平板）標籤只顯示名稱；七個字的名稱在「與」之後換行。樞紐標籤是「中央樞紐」，寬螢幕下方加「互動實驗島」。
- **以文字說明拓樸**：導覽面板新增「世界橋樑」一節，列出樞紐橋與四座關聯橋的兩端；Canvas 的無障礙名稱也說明橋的數量。不看 3D 也能知道拓樸。
- **Draw call**：兩種橋各一個合併網格，總覽共 15 個 draw call（P8.2 為 14）。

總覽的幾何（輪廓位置、橋的端點、鏡頭取景、標籤位置）都移到不含繪圖程式的函式庫（[world-overview-geometry.ts](../../src/lib/islands/regions/world-overview-geometry.ts)），場景只負責畫；所以上表的規則是資料層的單元測試，而 E2E 另外確認「頁面實際畫的橋」與「函式庫算出的橋」相差不超過 1.5 px。

## 6. Mobile UX 驗收

### 6.1 驗收方式

P8.2 把手機總覽的島寬下限由 80 改成 70 來讓測試通過；那個門檻已移除。現在分成七項，各自有自己的標準（`e2e/world-topology.spec.ts`，在 320×568、375×812、390×844 各跑一次，五個 Region）：

| 項目 | 標準 |
|---|---|
| 1. Region Overview 的整體輪廓 | 每座島完整在地圖內；群島本身（不含圖釘與周圍留白）佔地圖寬度 ≥ 70%；每座島至少是一個觸控目標（≥ 44 px） |
| 2. Island Focus 的單島辨識 | 29 座島逐一聚焦：寬度 ≥ 88 px、完整在地圖內、在科目面板上緣之上、中心點上方沒有地圖以外的元素、地圖仍在視窗內 |
| 3. 互動標籤碰撞 | 每座島一個圖釘；圖釘彼此不重疊、都在地圖內。世界總覽：標籤彼此不重疊、不壓橋、不蓋島 |
| 4. Touch Target | 圖釘、島嶼清單、地圖按鈕、標頭的返回與清單按鈕、清單下方的連結：寬與高都 ≥ 44 px（含看不見的觸控區） |
| 5. Camera Bounds | 用地圖自己的方向鍵往四個方向各推 30 次：仍有島的中心在地圖內，按 0 回到全景；縮到最遠：整個群島仍在地圖內且寬度 ≥ 40% |
| 6. Drawer／Bottom Sheet | 總覽狀態地圖上被其他元素蓋住的取樣點 ≤ 2%；科目面板最多佔地圖 60%；關閉面板後島回到整張地圖取景；島嶼清單在地圖下方而不是上方 |
| 7. 尺寸 | 320、375、390 px 三種都跑 |

總覽狀態不要求每座島 88 px：在那個狀態，分辨島嶼靠的是整體輪廓、每座島自己的圖釘（44 px 觸控區）與下方清單；88 px 是聚焦後的標準，而且現在是對全部 29 座島檢查（P8.2 每個 Region 只抽一座）。

| 問題 | 影響 | 修法 |
|---|---|---|
| **相機移動後沒有要求重繪**（既有，`frameloop="demand"`）：切換聚焦的島時，取景指令有時在那一幀之後才發出，之後沒有任何東西要求下一幀，畫面停在舊位置，直到下一次觸碰 | 修正前的量測：87 次切換聚焦中有 14 次，鏡頭在 6 秒內沒有到位（島在畫面外，或仍在面板後面） | `hex-camera.tsx` 的取景 effect 結尾呼叫 `invalidate()`。首頁與 `/islands` 逐像素不變（§8.3） |
| **科目面板蓋住聚焦的島**（手機，已開放的四座 CS 島）：面板浮在地圖下方 56%，鏡頭卻把島放在整張地圖的正中 | 島有一半以上在面板後面 | 區域地圖在單欄螢幕把面板高度交給相機，島取景在面板上緣之上；關閉面板後回到整張地圖。只有區域地圖啟用（`phoneRoom`），首頁不變 |
| **320×568 的總覽被不存在的覆蓋層佔掉高度**：相機為「地圖上方的標題、下方的按鈕列」各留 72／96 px，但區域地圖在手機上這兩者都在地圖之外；圖釘也被當成文字名牌留了寬度 | 320 px 時島只有 47–58 px | 區域地圖在手機只留圖釘需要的空間（上 30、下 26 px；側向 3.2 格）。320 px 的最小島寬 47 → 63 |
| **方向鍵上下平移會越界**（P8.2 的鍵盤操作）：`truck` 沿相機自己的上方向移動，把視線中心抬離地面，不受地圖邊界限制 | 按住上或下，整張地圖移出畫面 | 上下改用 `forward`（沿地面移動，與拖曳相同）；邊界改為各島中心的外框（原為含岸邊與名牌點的外框，在手機上可把斜向的 CS 群島推到只剩島尖） |
| **標頭的返回與清單按鈕小於 44 px**（35×34、34×26） | 觸控目標不足 | 與圖釘相同的作法：外觀與標頭高度不變，加上看不見的 44 px 觸控區。只作用於區域地圖頁 |

### 6.4 沒有涵蓋或留待處理

- **真機**：全部是 Chromium 的視窗尺寸模擬；iOS Safari、Android Chrome 真機沒有測。
- **320 px 的全站標頭**：主選單在 320 px 換成兩行（「探索群／島」），這是全站標頭既有的行為（`/world` 之外也一樣），本階段沒有動。
- **全站導覽連結與試煉入口的高度**：標頭主選單 34 px、區域頁尾的試煉入口 32 px，都小於 44 px；它們屬於全站標頭與 trials 模組，本階段沒有動。
- **聚焦時其他島的圖釘會畫在科目面板之上**（層級既有行為，首頁相同）。不影響點選，但視覺上不乾淨；修改需要動共用樣式，留待審核。
- **平板寬度的區域地圖**：1024 與 834 px 寬時，區域地圖有名牌跑到清單下方或地圖外（P8.2 即如此，首頁在這些寬度也有同樣情形）。世界總覽在 1024 px 是乾淨的。
- **1280 px 的 `/world/ai`**：「AI 工程與 MLOps 島」名牌的右緣與清單面板重疊約 3 px（P8.2 即如此）。修法是把 AI 的 `labelReach` 由 6 調到 6.5，但那會改動 AI 的桌機取景，本階段依指示不動 AI 配置，列為待審。
