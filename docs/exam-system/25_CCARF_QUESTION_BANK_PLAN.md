# 25 CCAR-F 原創題庫與模擬考開發計畫（T.3A）

本文件是 T.3A 研究與設計的成果。本輪**不製作題目**，也**不改動 Trials Engine**。

- 官方事實見 doc 23。
- 考綱矩陣與配額見 doc 24。
- 本文件的所有設定都是 **Logic Island 自訂**。只有直接引用 doc 23 的內容才是官方確認。

## 1. 定位與界線

- **定位**：CCAR-F 島是依官方考綱學習 Claude 架構設計的練習。它**不是**官方考題、官方模擬考或認證準備保證。每份卷、每個結果頁都要寫明「Logic Island 原創練習，非官方試題，與 Anthropic 認證無隸屬關係」。
- **適用對象**：官方只開放 Claude Partner Network 成員報考（doc 23 §2）。題庫的教學價值不依賴應考資格。
- **禁止使用的素材**：
  - 官方考試指南的 12 題範例題，不複製、不改寫，也不作為模板。
  - 考生回憶題與「題庫」網站。
  - 官方 6 個情境的名稱與設定。
  - 任何標示機密的考試內容。
- **允許的依據**：
  - 官方考綱，作為**範圍**。
  - 公開的官方技術文件，作為**事實**：Claude API、Agent SDK、Claude Code、MCP。
  - Logic Island 自行撰寫的情境。

## 2. 題庫規模與階段

| 階段 | 題數 | 內容 | 建議輪次 |
|---|---:|---|---|
| MVP | 100 | 依 doc 24 MVP 欄。全部單選，每題附獨立短情境。分 4 批，每批 25 題 | T.3B |
| 擴充 | +100，共 200 | 依 doc 24 擴充欄。加入複選題約 15%，以及情境組 | T.3C |

- 批次大小與 iPAS 相同：每批 25 題，一位撰寫者負責一個批次檔，審查者另外抽查。
- 題目 ID：`ccarf-a-01`～`ccarf-d-100`，擴充批次從 `ccarf-e-101` 起。

## 3. 原創題規範

1. **一題一考點**：每題恰好有一個任務陳述標籤（`ccarf.dN-M`）和一個子主題標籤（`claude.*`）。
2. **情境優先**：官方題目全部是情境題（doc 23 §3）。題型比例是情境 80%、應用 15%、概念 5%，沿用 `stemShape`。
3. **四個選項，一個正解**：
   - 錯誤選項必須是「看似合理的常見誤解」，例如靠解析自然語言判斷是否結束、用迴圈上限當主要停止條件、把秘密值寫進 `.mcp.json`。
   - 不使用「以上皆是」或「以上皆非」。
4. **答案可驗證**：
   - 每題的解析必須引用官方公開技術文件的頁面與段落（附 URL 與查證日期）。
   - 能用程式驗證的考點必須在本機實際驗證，並把驗證方式記在審核備註，例如 `stop_reason` 的值、`tool_choice` 的行為、CLI 旗標。
   - 無法驗證的考點不出題。
5. **解析格式**：沿用 iPAS 的格式，「正解（X）。」之後逐一說明其他三個選項為何錯。
6. **語言**：
   - 題目用繁體中文。API 名稱、參數、旗標、檔名與工具名稱保留原文，例如 `stop_reason`、`allowedTools`、`.mcp.json`。
   - 官方考試是英文與日文，在說明頁註明這點。
7. **不出排除範圍**：doc 23 §4.2 列出的 14 項排除範圍不出題。
8. **不依賴版本細節**：
   - 優先考設計判斷，例如何時用 hook、何時用提示。
   - 少考某版本才有的參數名稱。
   - 必須考版本細節時，一律標成易變題（§7）。

## 4. 難度、題型與情境比例

| 維度 | MVP（100） | 擴充後（200） |
|---|---|---|
| 難度 1（定義、辨識） | 5% | 5% |
| 難度 2（單一概念應用） | 30% | 25% |
| 難度 3（情境判斷、取捨） | 50% | 50% |
| 難度 4（多步推理、多考點交互） | 15% | 20% |
| 情境／應用／概念 | 80／15／5 | 80／15／5 |
| 單選／複選 | 100／0 | 約 85／15 |
| 情境組（一個共用情境加 5 題） | 0 | 10 組 50 題，涵蓋 6 類原創情境 |

原創情境類型如下。它們都是 Logic Island 自訂，名稱與設定不與官方 6 個情境重疊。

1. 電商退貨審核 agent，需要升級給人工。
2. 內部文件問答與出處標示。
3. 多來源市場研究的 coordinator 與 subagent。
4. 團隊導入 Claude Code 的設定治理。
5. CI 中的自動審查與修正。
6. 表單與發票的結構化抽取。

情境組可以讓同一份卷保有「同一情境多題」的作答體驗。

難度標定與 iPAS 相同，採盲測校準：審查者不看答案作答，依答對率與耗時調整等級。

## 5. 驗證、相似性與審核

| 關卡 | 內容 | 工具 |
|---|---|---|
| 匯入檢查 | schema、標籤、四個選項、解析格式、易變題日期 | `scripts/trials/import.ts`（既有，dry run → write → 冪等） |
| 答案驗證 | 解析引用的文件 URL 可開啟，且內容支持正解；可驗證的行為已實測 | 審核清單 `answer-verified`、`source-checked` |
| 原創性 | 與官方範例題比對：只在本機以原文做相似性比對，**原文不進 Git、不進文件** | `scripts/trials/similarity.ts`，以 `--against` 指向本機私有目錄 |
| 題庫內相似 | 同題庫內重複考點建立衝突圖，避免同卷出現 | `src/content/trials/conflicts.ts` 的同一機制 |
| 盲測審查 | 獨立審查者先作答，再看答案與解析 | 與 T.2E 相同的流程 |
| 人工核准 | 只有人工的決定檔透過 `review.ts apply` 寫入帳本。AI QA 只提供建議 | T.2C 帳本、T.2F 的 `review.ts queue/packet/summary` |
| 發布 | `publish.ts` 驗證修訂版與 hash | T.2C 發布閘門 |
| 發布前檢查 | `preflight.ts` 加上 CI | T.2F |

相似性門檻沿用 iPAS 的設定：中風險以上要改寫或重新設計，並記錄在審核佇列。

## 6. 模擬考設定（Logic Island 自訂）

| 模式 | 題數 | 時間 | 計分顯示 |
|---|---:|---:|---|
| 官方規格練習 | 60 | 120 分鐘 | 原始分數與答對率、各 domain 答對率。**不顯示通過與否，也不換算尺度分數** |
| 延長練習 | 60 | 150 分鐘 | 同上 |

- 官方是尺度分數 720／1,000 及格，但沒有公布換算方式（doc 23 §3）。因此 Logic Island 不顯示「通過」，也不宣稱答對多少百分比等於及格。
- 官方規格模式的 `passPoints` 留空，`passBasis` 寫明「官方以尺度分數 720 及格，換算方式未公布，本練習不判定通過」。
- 每題 1 分是 Logic Island 的假設。複選題全對才得分，因為官方沒有說明部分給分（doc 23 §3）。
- 成績頁的各 domain 答對率可以對應官方成績單的呈現方式（doc 23 §3）。

## 7. 時效管理

- **易變題**：寫到 API 參數或回傳值、CLI 旗標、設定檔格式、SDK 型別或函式名稱、內建工具名稱的題目，都標 `meta.volatile`。`reviewBy` 設為 **90 天**（iPAS 是 6 個月），因為 Claude 產品更新較快。
- **預期易變題比例**：MVP 約 35–45%，主要集中在 D2.4、D2.5、D3 與 D1.3。
- **官方指南監看**：每 90 天重新查證 doc 23 的 S1 與 S2。版本號或權重一有變動：
  1. 更新 doc 23、24 與 blueprint 資料。
  2. preflight 的「官方來源」檢查會讓舊版本的模擬考失敗。
  3. 受影響的題目送回審核。
- **發布阻擋**：已發布的易變題一旦過了 `reviewBy`，preflight 判定失敗（T.2F 既有規則），題目要重新審核後才能繼續出現在卷中。

## 8. 與既有 Trials Engine 的整合

原則：沿用既有的資料結構與流程，以資料驅動設定，**不建立第二套 Trials Engine**。

| 元件 | 沿用方式 | 需要的擴充 |
|---|---|---|
| Question Schema | 直接沿用：revision、hash、review、provenance、`stemShape`、`reviewBy` | 無 |
| 考綱標籤 | 新增 `ccarf.d1`～`ccarf.d5` 與 30 個任務陳述標籤，各帶 `syllabus.code` | `syllabusCodeOf` 目前寫死 `ipas.` 前綴。改為依標籤的 `syllabus` 欄位（官方考綱來源）取代碼，iPAS 行為不變 |
| 來源 | 新增 `ccarf-exam-guide-1-0`（kind `official-syllabus`，`version: '1.0'`），以及 `basis-ccarf` 原創依據 | 無 |
| 考試／版本／科目 | `exams.ts` 新增 `ccarf`、版本 `ccarf-2026-07`、科目 `ccarf-2026-07.foundations`，format 為 60 題、120 分鐘，`passPoints` 不設 | 科目 format 已允許省略 `passPoints` |
| Importer | 直接沿用：批次檔放 `batches/`，產出放 `generated/` | 無 |
| 審核帳本與發布閘門 | 直接沿用：同一份 `ledger.json`、`published-hashes.json` | 無 |
| 審核作業（T.2F） | `review.ts --exam ccarf` | 審核佇列檔目前固定是 iPAS（`ipas-review-queue.json`），需改成依考試選擇佇列檔 |
| 動態組卷 | `MockBlueprint`：coverage 用 30 個任務陳述代碼，見 doc 24「卷」欄 | `MockBlueprint.coverage` 的鍵目前是 iPAS 代碼，改為通用的考綱代碼即可。情境組要讓 `drawPaper` 支援「組」抽樣（T.3C） |
| 模式 | `mockModes` 改為依考試設定：CCAR-F 用 120 與 150 分鐘、不判定通過 | `mockModes` 目前是 iPAS 專用常數，改為各 blueprint 自帶 modes（型別已支援） |
| Exam Session、計時、恢復 | 直接沿用 | 無 |
| 計分 | 單選直接沿用 | 複選題：`MVP_TYPES` 加入 `multiple-choice`，engine 判分改為「選項集合完全相同才得分」，作答 UI 用 checkbox 並顯示「選 N 個」（T.3C） |
| 錯題複習 | 直接沿用 | 複選題的作答顯示（T.3C） |
| 成績頁 | 各考綱項目表現沿用，改為依 domain 彙總 | 結果頁的考綱表需支援兩層（domain 與任務陳述） |
| Preflight 與 CI | 直接沿用，blueprint 一加入就納入檢查 | 無 |
| 曝光防護 | 沿用：未發布前不產生路由，入口顯示「題目準備中」 | 新增群島入口（`entries.ts`） |

T.3B 的最小改動集合：

1. `syllabusCodeOf` 改為通用。
2. 審核佇列依考試選擇。
3. modes 改為依 blueprint 設定。

這三項都是純資料或小型重構，必須用現有 iPAS 測試證明行為不變。

複選題與情境組留到 T.3C，因為它們是 engine 的功能擴充，需要另外取得授權。

## 9. 生命週期

```
撰寫（batch JSON） → AI QA（schema、格式、相似性、可驗證性）→ 匯入（in-review，第 1 版）
  → 審核封包（review.ts packet --exam ccarf --sort risk）→ 人工決定檔 → review.ts apply（帳本）
  → publish.ts（修訂版加 hash）→ preflight 與 CI → 各任務陳述配額滿足 → 自動組卷出現
```

- 修改題目會產生新的修訂版，需重新審核。
- 易變題到期後送回審核。
- 官方指南改版時，依 §7 重新核對考綱與題目。

## 10. 風險與待決事項

| 風險 | 對策 |
|---|---|
| 官方範例題或第三方題庫滲入 | 相似性比對（原文只在本機）、撰寫者聲明、審查者抽查 |
| 產品更新使答案過時 | 易變題 90 天複查、解析附查證日期、preflight 阻擋過期題 |
| 繁中翻譯造成概念偏差 | 技術名詞保留原文；每批由一位熟悉英文文件的審查者核對 |
| 被誤認為官方題 | 每頁標示非官方；不使用官方情境名稱；不顯示通過 |
| 官方條款限制 | Certification Terms 與 Exam Policy 兩份 PDF 須在 T.3B 開始前由人工閱讀確認（doc 23 §8） |
