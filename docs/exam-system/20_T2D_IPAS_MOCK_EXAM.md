# 20 iPAS 模擬考整合（T.2D）

- **範圍**：iPAS AI 應用規劃師（初級）兩科模擬考的設定、只用已發布題目組卷、作答、計時、交卷、評分、成績分析與錯題練習。
- **重用**：沿用 T.0 的考試引擎（`src/lib/trials/engine.ts`）、本機紀錄（`store.ts`）、錯題本、試煉頁面與 T.2C 的發布關卡；沒有建立第二套引擎。T.2C 的安全語意不變。
- **現況**：iPAS 100 題全部 `in-review`，所以**沒有任何 iPAS 試卷被組出**，網站上的 iPAS 入口仍是「題目準備中」。

## 1. 兩份模擬卷設定（`src/content/trials/mock-exams.ts`）

| 項目 | 科目一 L11 | 科目二 L12 |
|---|---|---|
| 藍圖 ID | `ipas-aiap-basic-s1-mock-a` | `ipas-aiap-basic-s2-mock-a` |
| 題目 | 該科 50 題（Q01–Q50），依考綱順序 | 該科 50 題（Q51–Q100），依考綱順序 |
| 考綱涵蓋 | 9 項評鑑內容，題數依 12 §5.2 | 7 項評鑑內容，題數依 12 §5.2 |
| 題型 | 單選題 | 單選題 |
| 時間 | 120 分鐘 | 120 分鐘 |
| 計分 | 每題 2 分，答錯或未作答 0 分，滿分 100 | 同左 |
| 通過與否 | 不判定 | 不判定 |

**與官方規則的差異**（寫在試卷說明中，不宣稱為官方規則）：

- 時間：本模擬 120 分鐘；官方簡章（115.04 版）為每科 75 分鐘。
- 配分：官方只公告每科 100 分，沒有公告每題配分或是否倒扣；每題 2 分是 Logic Island 的設定。
- 及格：官方簡章為單科 70 分及格，兩科同時報考者平均 70 分以上且每科不低於 60 分才授證。因為本模擬的時間與官方不同，成績頁**不顯示通過或未通過**，只顯示分數與學習建議，並附上簡章的規定供參考。

## 2. 只用已發布題目組卷（`src/lib/trials/mock-assembly.ts`）

- **結構檢查**（不論是否發布）：剛好 50 題、Question ID 不重複、每題只屬於該科、單選題、考綱涵蓋與題數符合規劃、依考綱順序排列。
- **發布檢查**：每題的目前版本必須是 `published`，而且
  - 經過 T.2C 發布關卡：題目的發布紀錄就是目前版本與目前內容雜湊，且 `published-hashes.json` 記錄相同雜湊；或
  - 在 T.2C 以前已發布（只有既有 53 題）：`published-hashes.json` 記錄的雜湊等於目前內容。
- 審稿中、已核准未發布、發布紀錄過期（內容已修改）或雜湊不符的題目，都不會進入試卷；整份藍圖回報「未就緒」與原因，**不會刪題、補題或混入其他科目**。
- 組出的試卷把每題固定在已發布的版本，並再經過 `validateTrials` 的試卷檢查（題目必須可上線、屬於該科）。
- 試卷只有在 50 題全部就緒時才加入題庫（`readyMockPapers`）。目前沒有任何一份就緒，所以不產生 iPAS 路由。

### 避免同卷的配對

docs 15–18 記錄了考點相近、建議避免同卷的配對：科目一 23 組、科目二 16 組（另有 1 組跨科配對，不可能同卷）。固定的 50 題試卷包含該科全部題目，所以**每一組配對都必然同卷**。

- 處理方式：保留試卷完整性，每組配對都列為組卷**警告**（`checkBlueprint` 的 `warnings`，測試核對數量與 review queue 一致），不刪題、不替換。
- 未來擴充方案：每科題庫擴充到 75～100 題後，改為由藍圖抽題的生成式試卷（schema 已預留 `kind`），組卷時把配對設為互斥條件，才能真正避免同卷。

## 3. Production 與 Preview 的隔離

| 模式 | 用途 | 可用題目 | 如何啟用 |
|---|---|---|---|
| Production | 網站 | 只有已發布、雜湊相符的版本 | 預設；`src/content/trials/index.ts` 只加入就緒的試卷 |
| Preview／Test | 自動化測試 | 審稿中的 iPAS 題目 | 只能在 Vitest 中呼叫 `previewPaperView`（`src/lib/trials/mock-preview.ts`） |

- Preview 在非 Vitest 環境（建置、開發伺服器、瀏覽器）一律拋出錯誤；沒有任何頁面或元件引用它（`tests/trials-exposure.test.ts` 靜態檢查）。
- Preview 不寫入任何檔案：不新增審核紀錄、不寫入發布帳本、不把試卷加入題庫。沒有任何公開的預覽路由。

## 4. 作答體驗（`src/components/trials/exam-runner.tsx`）

- **開始前**：顯示科目、題數、作答時間、計分方式、考試須知與免責說明；按下「開始」才計時。
- **作答**：一次顯示一題；上一題／下一題；題號導覽（已作答、未作答、已標記，目前題號以 `aria-current` 標示）；「標記稍後檢查」；作答進度。切換題目時，焦點移到該題標題，螢幕閱讀器從新題目開始朗讀。
- **計時**：以 session 的絕對截止時間計算，切換題目、重新整理或關閉分頁都不會重設；120 分鐘以「時:分:秒」顯示；只在剩 5 分鐘與 1 分鐘時提示，不會每秒朗讀；時間到自動交卷。
- **本機計時的限制**：網站沒有伺服器端考試 session，計時以瀏覽器時間為準，無法防止使用者修改瀏覽器資料或時間；開始畫面已說明，成績只供自我練習。
- **交卷**：每次交卷都要確認，確認框顯示未作答與已標記的題數；重複點擊只評分一次；交卷後作答畫面關閉，答案不能再修改（引擎也拒絕交卷後的作答）。
- **無障礙**：原生的按鈕、單選鈕與 fieldset／legend；導覽按鈕有完整的狀態標籤；可見的焦點框；按鈕、選項、導覽按鈕與篩選按鈕的觸控目標至少 44px；窄螢幕時題號導覽移到題目下方。

## 5. 評分與成績

- 引擎的純函式：每題 2 分、答錯或未作答 0 分；`summary` 回傳答對、答錯、未作答、正確率與作答時間（測試涵蓋）。
- 成績頁：分數、答對／答錯／未作答、正確率、作答時間、**各考綱項目表現**（題數、答對、得分、正確率，低於 60% 標為「需加強」）、建議先複習的項目與相關課程。
- 逐題檢討：可篩選全部、答錯、未作答、已標記；每題顯示作答、正確答案、正解解析與三個錯誤選項的解析、考綱項目與出處。

## 6. 錯題練習

- 交卷後，答錯與未作答的題目進入既有的錯題本（`/trials/review`），可以重新作答，同一題連續答對 2 次就算精熟。
- 紀錄只保存在這個瀏覽器（localStorage），不跨裝置同步，也不能防作弊；成績頁與錯題本都已說明。
- localStorage 只保存 session 的題目 ID、版本、雜湊、選項順序、作答與成績，不保存題幹、選項文字或解析（測試確認）。
- 錯題本只顯示已發布的題目；iPAS 題目發布後才會出現在網站的錯題本。
