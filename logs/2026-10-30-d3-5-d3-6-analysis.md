## 2. 重要技術發現

1. **看不到真正的天空**：正交、俯視約 36° 的等角視角沒有地平線，畫面幾乎全是海面；背景色只在深海框（±200）以外才露出。「天空」在本視角實際由**背景色、半球光的天空色、海面色調**表達。若要畫出可見的天空漸層，需要改透視相機並允許接近水平的仰角，這是另一個層級的改動，**不建議在 D.3-6 做**。可選的低成本做法是在舞台上方加 CSS 漸層覆蓋（0 draw call），屬視覺決策。
2. **低太陽的陰影需要調整陰影相機**（2026-10-30 修正，見 §0.1 #6）：仰角越低，固定大小的陰影相機在地面上的覆蓋反而越大，所以不是「地形落在範圍外」。真正的問題是光源距離固定約 27 時向光側較遠的物件被近平面裁掉、陰影貼圖沿太陽方向拉長約 1.9 倍，以及 bias。建議黃昏仰角取 **25～30°**（陰影長度約 1.7～2.1 倍物高），並依光源方向把世界包圍盒投影到光空間，一起算出範圍、near／far 與光源距離；陰影 bias 依情境調。
3. **靜態陰影可以支援不同太陽角度**：切換情境時設一次 `gl.shadowMap.needsUpdate = true`（或把光源方向放進 `StaticShadows` 的判斷鍵），每次切換只多畫一次陰影，平時成本不變。
4. **傍晚燈光幾乎免費**：GLB 已有獨立的 `LLv2_Warm_Emission` 材質，執行時調高 `emissiveIntensity` 即可，**不改 GLB、不加 draw call**。沒有 bloom，只會看到亮色而沒有光暈；需要光暈時可加一組 additive 的 instanced 光點（+1 draw call）。**不建議用 PointLight**：每盞燈都會讓所有 `MeshStandardMaterial` 的片段著色多一份計算並觸發 shader 重新編譯，手機成本最高。
5. **霧會觸發 shader 重新編譯**：`scene.fog` 從無到有會讓所有材質重新編譯（首次切換卡頓）。建議一開始就放一個 `Fog`，中午把 near／far 拉到看不到，只改參數。正交相機下的霧依深度分布，效果是畫面前後的淡化，比透視相機弱。
6. **自由旋轉會打破兩個「固定 VIEW」假設**：取景計算與全景名牌掛向都用固定的 `VIEW`。旋轉後聚焦要用「目前方位角＋預設仰角」重新算畫面軸；名牌掛向要在相機靜止（`rest`）時依目前方位重算，否則某些角度名牌會蓋到島上。
7. **Auto Orbit 會讓畫面持續重畫**：`frameloop="demand"` 下環繞期間每幀都要畫，GPU 負載等同一直在鏡頭飛行（P-01 的情境），另外每幀還要更新 drei `Html` 名牌的 DOM 位置。必須預設關閉、分頁隱藏時停止，並在 D.3-4B 量測。

## 4. 需求對應與技術選型

### 4.1 D.3-5 Camera Controls

| 需求 | 做法 |
|---|---|
| 桌機拖曳旋轉、滾輪縮放 | `mouseButtons.left = ROTATE`、`wheel = ZOOM`（正交相機用 zoom，可評估 `dollyToCursor`） |
| 手機單指旋轉、雙指縮放 | `touches.one = TOUCH_ROTATE`、`two = TOUCH_ZOOM`；點擊與拖曳由既有 `delta >= 6` 區分。**已決定方案 B**：外層 div 與 canvas 改 `touch-action: pan-y`（在 camera-controls 連接後寫回），垂直滑動交給瀏覽器捲頁（控制器收到 pointercancel 結束拖曳），觸控時仰角固定 |
| Auto Orbit 開關 | Explorer 的切換按鈕（`aria-pressed`）；Canvas 內以 `useFrame` 呼叫 `controls.rotate(速度×delta, 0, false)`，約 6°／秒（一圈 60 秒），繞目前目標（聚焦島或世界中心） |
| 手動操作立即停止 | 監聽 `controlstart` 事件，回報 Explorer 關閉 orbit；**滾輪不觸發 `controlstart`，另外監聽滾輪**（§0.1 #1） |
| 點擊島嶼停止旋轉、保留飛行 | 選島時先停 orbit 再走既有飛行；飛行用「目前方位角＋預設仰角」重新取景 |
| 返回全景恢復預設角度 | 全景一律回到 `VIEW` 方向與原本的取景；只要視角偏離預設（含全景時旋轉或縮放）按鈕就可用（§0.1 #3）；改變視窗大小保留方位角（§0.1 #4） |
| 限制俯仰、縮放、旋轉 | 仰角限制約 **28°～60°**（`min/maxPolarAngle`，避免接近水平看到海面外框或模型底部）；`minZoom` 依全景取景值設下限，避免縮到看見深海框邊緣；方位角**預設不限**（環繞需要 360°），若評估後某些角度不理想再以 `min/maxAzimuthAngle` 限制。低仰角拉遠時另需防止近平面切到海面（§0.1 #12） |
| reduced motion | Auto Orbit 預設關閉；飛行沿用現有「不動畫」；使用者主動開啟時才環繞 |
| 不破壞名牌、3D 點擊、BFS、清單、fallback | ~~名牌是 DOM（drei `Html`），事件不進控制器~~（**錯誤**，見 §0.1 #11：名牌在控制器監聽的元素裡，需要 6 px 拖曳判斷）；清單模式與 fallback 時 Canvas 不存在；BFS 是頁面連結 |

### 4.2 D.3-6 Time-of-Day Environment

| 情境 | 太陽（仰角／方位） | 主要變化 |
|---|---|---|
| 清晨 Morning | 約 25°，東 | 淡金主光、較低環境光、淡藍粉背景、輕霧（近端起霧）、海面偏淺 |
| **中午 Noon（預設）** | 維持現值（約 55°） | **與目前 `contrast` 光照逐項相同**：預設情境畫面不變 |
| 黃昏 Sunset | 約 25～30°，西 | 橘金主光、暖色半球光、長陰影、海面偏暖 |
| 傍晚 Dusk | **約 40° 月光**（已決定；10° 低太陽的陰影會長 5～6 倍） | 藍紫背景與半球光、整體亮度降低、`LLv2_Warm_Emission` 強度提高（燈塔與路燈發亮；只複製這個材質，見 §0.1 #7） |

- UI：四選一的 radio group（或在 360 px 改用原生 `<select>`），中午預設。**D.3-3 規定手機工具列維持一行**，所以控制項放在舞台下方的提示列（與「返回全景」同列）或一個小面板，不放進工具列；最終位置需視覺確認。
- 切換方式：一次性更新 uniform（光色、強度、背景、霧參數、海面材質 `color` 乘上烘焙貼圖、發光強度）＋一次陰影重畫。**不重建幾何、不重新烘焙海面貼圖**。
- 不做 24 小時連續循環；不做切換動畫（若要，可在 0.5 秒內內插 uniform，但會連續重畫數十幀，列為可選）。

## 7. 對桌機、手機與 WebGL fallback 的影響

| 面向 | 影響 |
|---|---|
| 桌機 | 拖曳與滾輪從「無作用」變成旋轉與縮放；滾輪縮放會攔截頁面捲動，只在指標位於地圖上時發生（**已決定直接縮放**） |
| 手機 | 單指在地圖上從「無作用」變成水平旋轉；**方案 B（已決定）讓垂直滑動恢復捲頁**（P1-27），iOS Safari 行為需真機確認（T-06）。點擊與拖曳用 6 px 門檻區分 |
| WebGL fallback | 不受影響：清單模式與 fallback 時 Canvas 不存在；相機與環境控制項只在 3D 模式顯示，fallback 時隱藏或停用 |
| 鍵盤與無障礙 | Orbit 按鈕、時間選擇要能用 Tab／Enter／方向鍵操作並有名稱；自動移動的內容必須可暫停（WCAG 2.2.2），按鈕即滿足；旋轉本身沒有鍵盤操作，鍵盤使用者仍用名牌與清單導覽（可選：方向鍵旋轉） |
| 舊版 | 不變 |

## 10. 與 Phase E JSON 島嶼配置的整合

- `environments.ts` 的情境是純資料，型別即未來 schema 的一部分；Phase E 的島嶼／世界 JSON 可加 `scene.environment: { default: 'noon', presets?: { [name]: Partial<EnvironmentSpec> } }`，載入後以同一個驗證函式檢查（色碼、範圍、仰角上限）。
- 相機限制同樣以資料表達：`scene.camera: { polar: [28, 60], zoom: [min, max], orbitSpeed }`，延續 KNOWN_ISSUES P1-24（LOD 門檻要移進 `scene` 區塊）的方向。
- **本階段不建立 JSON 載入或 schema**，只讓資料形狀可直接被 E 使用。
